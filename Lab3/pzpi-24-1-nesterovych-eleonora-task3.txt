Харків - 2026

1. Мета роботи
Ознайомитися з процесом розроблення бізнес-логіки та функцій адміністрування серверної частини програмної системи. Набути практичних навичок реалізації бізнес-логіки й функцій адміністрування, побудови UML-діаграм діяльності та взаємодії, а також перевірки (тестування) роботи серверної частини.

2. Завдання
Для програмної системи «Програмна система для керування ресурсами навчального житлового модуля» (HabiCore) виконати такі завдання:
    • спроєктувати алгоритми бізнес-логіки, що забезпечують основні операції з даними, обробку запитів клієнтів і виконання специфічних правил роботи системи;
    • розробити функції адміністрування: керування користувачами та ролями, налаштування системних параметрів, моніторинг активності та доступ до журналу дій;
    • створити програмну реалізацію бізнес-логіки та функцій адміністрування серверної частини, включно з обробкою запитів до БД і взаємодією з клієнтами;
    • створити UML-діаграму діяльності та UML-діаграми взаємодії;
    • перевірити роботу розроблених функцій автоматизованими тестами та вручну;
    • оформити звіт, завантажити його у форматі PDF на платформу dl.nure.ua, а текстову версію звіту та код - у репозиторій GitHub.

3. Опис виконаної роботи
Роботу виконано відповідно до документа Vision & Scope [1]. Репозиторій проєкту розміщено на платформі GitHub: https://github.com/NureNesterovychEleonora/arkpz-pzpi-24-1-nesterovych-eleonora

3.1 Архітектура бізнес-логіки
Серверну частину, розроблену в лабораторній роботі №2, розширено окремим шаром бізнес-логіки. Архітектура складається з таких шарів:
    • шар маршрутизації HTTP (каталог src/routes): приймає запити, перевіряє автентифікацію та роль користувача, викликає сервіси й формує відповіді (додаток Г);
    • шар бізнес-правил (src/services/booking-rules.js, resources.js, request-rules.js): чисті функції без звернень до БД, які отримують дані та поточний час як параметри (додаток А);
    • шар сервісів (src/services/measurements.js, aggregates.js, booking-jobs.js, explanations.js, settings.js): алгоритми обробки даних, що працюють з БД через моделі ORM, і застосування системних параметрів (додатки Б, В і Г);
    • шар доступу до даних: моделі ORM Sequelize над БД SQLite.

Винесення правил у чисті функції дозволяє перевіряти їх модульними тестами без запуску сервера та БД. Сервіси створюються фабричними функціями, які отримують залежності (моделі, параметри, інші сервіси) як аргументи, тому, наприклад, звернення до зовнішньої мовної моделі в тестах замінюється тестовою функцією.
Узгодженість даних забезпечують такі рішення: створення та зміна бронювань і обробка вимірювань виконуються послідовно через чергу Mutex, тому одночасні запити не створюють перетину бронювань і не втрачають накопичену витрату ресурсів; поселення та виселення змінюють статус бронювання й створюють запис огляду в одній транзакції SQL; подія перевищення зберігається одразу, а пояснення до неї формується у фоновому режимі, тому пристрій отримує відповідь без очікування зовнішнього сервісу.
Фонові завдання виконує планувальник src/services/scheduler.js (додаток Б), який запускається разом із сервером: щохвилини оновлює статуси бронювань, а щоночі після 00:05 за київським часом розраховує добові агрегати за попередню добу, дораховує пропущені дати та видаляє застарілі сирі вимірювання. Системні параметри зберігаються у файлі settings.json, зміни якого застосовуються без перезапуску сервера, секретні значення (ключ підпису JWT, ключ API мовної моделі, дані першого адміністратора) - у змінних оточення.

3.2 Вибір технологій
Технології серверної частини збережено з попередньої роботи: Node.js, Express, ORM Sequelize і SQLite [1, 2, 3]. Транзакції Sequelize використано для атомарної зміни статусу бронювання разом із записом огляду [2]. Для приймання та видачі фотографій сервісних заявок застосовано вбудовані засоби Express (express.raw, express.static), а токен світлової сесії формується вбудованим модулем node:crypto (HMAC-SHA256) [8], тому додаткові бібліотеки не потрібні.
Пояснення перевищень формує зовнішня мовна модель Google Gemini [4], до якої сервер звертається стандартною функцією fetch з обмеженням часу очікування. Межі доби й час нічного завдання обчислюються за київським часом засобами Intl.DateTimeFormat [5]. Тестування виконується вбудованим засобом Node.js node:test [6], статичний аналіз - засобом ESLint.

3.3 Правила бронювання
Під час створення та зміни бронювання сервер перевіряє такі правила (додаток А):
    • час завершення пізніший за час початку;
    • тривалість не менша за значення параметра minBookingHours (1 година) і не більша за значення параметра maxBookingHours (24 години);
    • час початку нового бронювання не в минулому;
    • мешканець має не більше maxActiveBookingsPerUser (2) поточних і майбутніх бронювань; обмеження не діє для адміністратора;
    • бронювання не перетинається з іншими бронюваннями кімнати зі статусами created та active.
Мешканець може змінювати лише власні бронювання зі статусом created і скасувати бронювання лише до його початку. Адміністратор може створювати бронювання від імені інших користувачів і змінювати будь-які бронювання. Порушення правила повертає код 400 (некоректні дані) або 409 (конфлікт).

3.4 Поселення та виселення
Поселення виконується запитом POST /api/bookings/{id}/check-in, який надсилає Android-застосунок після сканування QR-коду кімнати. Тіло запиту містить QR-токен кімнати та результат огляду (стан ok або issues і необов’язкову примітку). Сервер перевіряє, що бронювання належить користувачу й має статус created, QR-токен збігається з токеном заброньованої кімнати, поточний час входить у вікно поселення (від 30 хвилин до початку до 60 хвилин після початку, але не пізніше кінця бронювання) і в кімнаті немає іншого активного бронювання. Після цього в одній транзакції бронювання отримує статус active і створюється огляд типу checkin; якщо огляд некоректний, статус не змінюється (додаток Г).
Під час поселення сервер також повертає токен світлової сесії lightToken. Токен обчислюється як перші 16 символів HMAC-SHA256 від ключа пристрою кімнати та номера бронювання. Android-застосунок передає його пристрою разом із BLE-командою світла, а пристрій, який знає власний ключ і номер активного бронювання з відповіді сервера, обчислює такий самий токен і приймає команду лише за збігу. Тому токен дійсний тільки протягом активного бронювання й перевіряється без звернення до сервера.
Виселення виконується запитом POST /api/bookings/{id}/check-out з результатом огляду. Активне бронювання отримує статус completed, створюється огляд типу checkout, а витрата води та світла, накопичена в полях бронювання waterUsed і lightUsed, фіксується та записується в журнал дій.

3.5 Потокова обробка вимірювань і контроль лімітів
Пристрій кімнати надсилає вимірювання запитом POST /api/measurements із заголовком X-Device-Key. Кожне вимірювання містить рівень води, освітленість, температуру та поточний режим світла (off, low, medium, high). Алгоритм обробки (додатки А і Б, рисунок Е.1) такий:
    • перевірка ключа пристрою та формату даних;
    • пошук активного бронювання кімнати, у межі якого потрапляє час вимірювання, і попереднього вимірювання кімнати;
    • збереження вимірювання в архів (повторне вимірювання з тим самим часом відхиляється з кодом 409);
    • розрахунок витрати між попереднім і поточним вимірюванням того самого бронювання: витрата води дорівнює зменшенню рівня в ємності (поповнення не враховується), витрата світла - добутку потужності режиму світла попереднього вимірювання на тривалість проміжку; проміжок обмежується параметром maxMeasurementGapSeconds, щоб тривала відсутність зв’язку не спотворювала облік;
    • додавання витрати до полів waterUsed і lightUsed бронювання;
    • виявлення перевищень: подія для води або світла створюється один раз - у момент, коли накопичена витрата вперше перевищує ліміт бронювання; подія для температури створюється, коли значення виходить за допустимий діапазон кімнати;
    • формування відповіді пристрою: поточні ліміти, використання лімітів, стан кімнати та перелік дозволених режимів світла.
Стан кімнати та дозволені режими світла визначаються за правилами, наведеними в таблиці 1. Поріг попередження задає параметр limitWarningRatio (0,8). Ці дані пристрій використовує для світлодіодної індикації та локального контролю режимів світла.

Таблиця 1 - Стан кімнати та дозволені режими світла
Умова	Стан	Дозволені режими світла
Немає активного бронювання, температура в діапазоні	normal	off
Використано менше 80% лімітів	normal	off, low, medium, high
Використано не менше 80% ліміту води або світла	warning	off, low (якщо поріг досягнуто для світла)
Ліміт перевищено або температура поза діапазоном	violation	off (якщо вичерпано ліміт світла)

Запит GET /api/rooms/{id}/resources повертає для ресурсної панелі та мобільного застосунку останнє вимірювання кімнати, використання лімітів активного бронювання (використано, ліміт, залишок, відсоток), стан і дозволені режими світла. Для графіка ресурсної панелі запит GET /api/rooms/{id}/history повертає вимірювання кімнати за останні 24 години (параметр hours), зведені в проміжки по 10 хвилин (параметр bucketMinutes): середні температура й освітленість, останні рівень води та режим світла в кожному проміжку (додатки А і Б).

3.6 Пояснення перевищень
Після збереження події перевищення сервіс пояснень (додаток В) формує технічний опис події: назва кімнати, ресурс, ліміт, фактичне значення, час, витрата бронювання, режим світла в момент виявлення (з вимірювання, що спричинило подію) та допустимий діапазон температури. Персональні дані користувача в опис не потрапляють, використовується лише ідентифікатор бронювання. Опис надсилається до Google Gemini API [4], відповідь приймається, якщо це непорожній текст довжиною до 600 символів.
Якщо ключ API не задано, вичерпано денний ліміт звернень (параметр llmDailyLimit), сервіс не відповів протягом 15 секунд або відповідь не пройшла перевірку, використовується шаблонне пояснення. Текст зберігається разом з подією з позначкою джерела llm або template, тому вебклієнт може позначити пояснення, згенероване штучним інтелектом. Мовна модель лише пояснює подію й не змінює даних системи.

3.7 Пакетна обробка та автоматичні статуси
Нічне завдання розраховує для кожної кімнати добовий агрегат за попередню добу за київським часом: мінімальну, максимальну та середню температуру й освітленість, витрату води та світла (додаток Б). Межі доби обчислюються з урахуванням переходу на літній і зимовий час. Розрахунок ідемпотентний: повторний запуск оновлює наявний запис, а не створює новий. Якщо сервер був вимкнений, під час наступного запуску завдання дораховує агрегати за пропущені дати, сирі вимірювання яких ще зберігаються. Сирі вимірювання зберігаються протягом періоду, заданого параметром measurementRetentionDays (14 діб), після чого нічне завдання їх видаляє; агрегати зберігаються без обмеження строку. Адміністратор може повторити розрахунок за будь-яку дату в межах періоду зберігання запитом POST /api/daily-aggregates/calculate, а звіт агрегатів за обраний період повертає запит GET /api/daily-aggregates з параметрами from і to.
Щохвилини планувальник виконує дві перевірки: бронювання зі статусом created, для якого минуло вікно поселення, скасовується з причиною no-show; бронювання зі статусом active, час якого завершився, отримує статус completed. Ці дії записуються в журнал без користувача (userId = null).

3.8 Сервісні заявки
Мешканець створює заявку з описом проблеми та додає фотографію запитом POST /api/service-requests/{id}/photo: зображення JPEG або PNG розміром до 5 МБ передається в тілі запиту, зберігається в каталозі data/uploads під випадковим ім’ям, а посилання на нього записується в поле photoUrl заявки. Адміністратор змінює статус заявки та додає коментар. Дозволено лише переходи new → in_progress → resolved і new → resolved; повернення до попереднього статусу відхиляється з кодом 409 (додаток А).

3.9 Функції адміністрування
Функції адміністрування доступні лише користувачам з роллю admin; перевірку виконує middleware авторизації, а заблокований користувач не може ні увійти, ні скористатися виданим раніше токеном. Реалізовано такі функції (додаток Г):
    • керування користувачами та ролями (/api/users): перегляд списку з фільтрами за роллю і блокуванням, створення, зміна імені, ролі й пароля, блокування та розблокування, видалення облікового запису; адміністратор не може заблокувати себе, зняти з себе роль адміністратора або видалити власний обліковий запис, тому система не залишиться без адміністратора;
    • редагування ресурсних лімітів кімнати (PUT /api/rooms/{id}): ліміти води та світла на бронювання і допустимий діапазон температури; нова кімната без явних лімітів отримує значення за замовчуванням із системних параметрів, а змінені ліміти одразу застосовуються під час обробки вимірювань;
    • журнал дій (GET /api/action-logs): фіксує вхід і реєстрацію, створення, зміну та видалення записів, поселення й виселення, автоматичні зміни статусів, розрахунок агрегатів, видалення застарілих вимірювань, зміну системних параметрів і завантаження фото; підтримує фільтри за користувачем, типом дії, сутністю й періодом, нові записи показуються першими;
    • моніторинг активності (GET /api/admin/stats): кількість користувачів за ролями та заблокованих, кількість кімнат, бронювань за статусами і сервісних заявок за статусами, п’ять останніх перевищень лімітів, а також кількість перевищень, вимірювань і записів журналу за останню добу;
    • системні параметри: тривалість і кількість бронювань, вікно поселення, ліміти за замовчуванням, поріг попередження, потужність режимів світла, період зберігання вимірювань, параметри мовної моделі та час нічного завдання задаються у файлі settings.json; поточні значення без секретів повертає запит GET /api/admin/settings. Змінений файл застосовується без перезапуску сервера: сервер відстежує зміну файлу, а адміністратор може застосувати його запитом POST /api/admin/settings/reload. Нові значення перевіряються (тип, допустимий діапазон, узгодженість мінімальної й максимальної тривалості та меж температури), некоректний файл відхиляється з кодом 400 і поточні значення залишаються без змін; перелік змінених параметрів записується в журнал дій (додаток Г).
Під час зміни запису універсальний CRUD-генератор порівнює значення полів до і після зміни та записує в поле details журналу перелік змін, наприклад «role: resident -> admin» або «waterLimit: 100 -> 20»; значення пароля в журнал не потрапляє. Взаємодію компонентів під час зміни ролі показано на рисунку Ж.2 (додаток Ж).

3.11 UML-діаграми діяльності та взаємодії
Послідовність дій основного бізнес-процесу - бронювання, поселення, використання кімнати з контролем лімітів, виселення та автоматичне скасування - показано на UML-діаграмі діяльності (рисунок Е.1, додаток Е). Діаграма містить вузли розгалуження за умовами виконання правил бронювання, вікна поселення та перевищення лімітів, а також цикл надсилання вимірювань протягом бронювання.
Обмін повідомленнями між пристроєм, Web API, сервісом обробки вимірювань, БД, сервісом пояснень і зовнішньою мовною моделлю під час обробки вимірювання з перевищенням ліміту показано на UML-діаграмі послідовності (рисунок Ж.1, додаток Ж): спочатку розраховується витрата між вимірюваннями (usageBetween), потім оновлюється накопичена витрата бронювання, після чого виявляються перевищення (detectViolations); фрагмент opt описує збереження події, а фрагмент alt - звернення до мовної моделі або резервне шаблонне пояснення. Взаємодію адміністратора з Web API, middleware автентифікації, CRUD-генератором і БД під час зміни ролі користувача та перегляду журналу дій показано на рисунку Ж.2.

'use strict';

const { createHmac } = require('node:crypto');
const { HttpError } = require('../middleware/errors');

// Правила бронювання. Функції не звертаються до БД: отримують дані
// та поточний час і або нічого не повертають, або кидають HttpError.

const MS_IN_MINUTE = 60 * 1000;
const MS_IN_HOUR = 60 * MS_IN_MINUTE;
const LIGHT_TOKEN_LENGTH = 16;

// Перевірка часу бронювання: кінець після початку, тривалість у межах
// від minBookingHours до maxBookingHours, початок не в минулому
// (для нового бронювання або при зміні часу початку)
function checkBookingTimes({ start, end, now, config, isStartChanged }) {
  if (end <= start) {
    throw new HttpError(400, 'endTime must be later than startTime');
  }
  const minHours = config.minBookingHours || 0;
  if (end - start < minHours * MS_IN_HOUR) {
    throw new HttpError(400, `Booking duration must be at least ${minHours} hour(s)`);
  }
  if (end - start > config.maxBookingHours * MS_IN_HOUR) {
    throw new HttpError(400, `Booking duration must not exceed ${config.maxBookingHours} hours`);
  }
  if (isStartChanged && start <= now) {
    throw new HttpError(400, 'startTime must be in the future');
  }
}

// Мешканець може мати не більше maxActiveBookingsPerUser поточних і майбутніх бронювань
function checkActiveBookingsLimit(activeCount, config) {
  if (activeCount >= config.maxActiveBookingsPerUser) {
    throw new HttpError(
      409,
      `A user can have no more than ${config.maxActiveBookingsPerUser} active and future bookings`,
    );
  }
}

// Вікно поселення: від checkInBeforeMinutes до початку
// до checkInAfterMinutes після початку (але не пізніше кінця бронювання)
function checkInWindow(booking, config) {
  const start = new Date(booking.startTime).getTime();
  const end = new Date(booking.endTime).getTime();

  return {
    opensAt: new Date(start - config.checkInBeforeMinutes * MS_IN_MINUTE),
    closesAt: new Date(Math.min(start + config.checkInAfterMinutes * MS_IN_MINUTE, end)),
  };
}

function checkCanCheckIn({ booking, room, qrToken, now, config }) {
  if (booking.status !== 'created') {
    throw new HttpError(409, 'Only bookings with status "created" can be checked in');
  }
  if (!qrToken || qrToken !== room.qrToken) {
    throw new HttpError(400, 'QR code does not belong to the booked room');
  }

  const { opensAt, closesAt } = checkInWindow(booking, config);
  if (now < opensAt || now > closesAt) {
    throw new HttpError(
      409,
      `Check-in is allowed from ${opensAt.toISOString()} to ${closesAt.toISOString()}`,
    );
  }
}

function checkCanCheckOut(booking) {
  if (booking.status !== 'active') {
    throw new HttpError(409, 'Only active bookings can be checked out');
  }
}

// Бронювання, на яке не поселилися вчасно, скасовується автоматично
function isNoShow(booking, now, config) {
  const { closesAt } = checkInWindow(booking, config);
  return booking.status === 'created' && now > closesAt;
}

// Активне бронювання автоматично завершується в момент закінчення
function isExpired(booking, now) {
  return booking.status === 'active' && now >= new Date(booking.endTime);
}

// Токен світлової сесії для BLE. Видається мешканцю під час поселення.
// Пристрій знає свій ключ і номер активного бронювання (з відповіді сервера),
// тому сам обчислює такий самий токен і перевіряє BLE-команду без звернення до сервера.
// Токен дійсний, лише поки це бронювання активне в кімнаті.
function lightSessionToken(deviceKey, bookingId) {
  return createHmac('sha256', String(deviceKey))
    .update(`light-session:${bookingId}`)
    .digest('hex')
    .slice(0, LIGHT_TOKEN_LENGTH);
}

module.exports = {
  checkBookingTimes,
  lightSessionToken,
  checkActiveBookingsLimit,
  checkInWindow,
  checkCanCheckIn,
  checkCanCheckOut,
  isNoShow,
  isExpired,
};

'use strict';

// Правила обліку ресурсів. Модуль не звертається до БД,
// тому його функції легко перевіряти модульними тестами.

const LIGHT_MODES = ['off', 'low', 'medium', 'high'];
const MS_IN_HOUR = 3600 * 1000;

const round = (value, digits = 4) => {
const factor = 10 ** digits;
return Math.round(value * factor) / factor;
};

const average = (values) => round(values.reduce((sum, v) => sum + v, 0) / values.length, 2);

// Витрата води та світла між двома сусідніми вимірюваннями.
// Вода - це зменшення рівня в ємності, світло - потужність режиму, помножена на час.
function usageBetween(prev, curr, config) {
if (!prev) {
return { water: 0, light: 0 };
}

const water = Math.max(0, prev.waterLevel - curr.waterLevel);

// Якщо зв'язок пропадав надовго, рахуємо не більше maxMeasurementGapSeconds
const gapMs = new Date(curr.measuredAt) - new Date(prev.measuredAt);
const countedMs = Math.min(Math.max(gapMs, 0), config.maxMeasurementGapSeconds * 1000);
const power = config.lightModePower[prev.lightMode] || 0;
const light = (power * countedMs) / MS_IN_HOUR;

return { water: round(water), light: round(light) };
}

function isTemperatureOutOfRange(temperature, room) {
return temperature < room.tempMin || temperature > room.tempMax;
}

// Частка використаного ліміту (1 = використано весь ліміт)
function usageRatio(used, limit) {
if (limit <= 0) {
return used > 0 ? Infinity : 0;
}
return used / limit;
}

// Знаходить нові перевищення після обробки вимірювання.
// usageBefore/usageAfter - накопичена витрата бронювання до та після вимірювання
// (null, якщо активного бронювання немає).
function detectViolations({ room, prev, curr, usageBefore, usageAfter }) {
const violations = [];

if (usageAfter) {
const resources = [
{ resource: 'water', key: 'water', limit: room.waterLimit },
{ resource: 'light', key: 'light', limit: room.lightLimit },
];

// Подія створюється один раз - у момент, коли витрата вперше перевищує ліміт
for (const { resource, key, limit } of resources) {
if (usageBefore[key] <= limit && usageAfter[key] > limit) {
violations.push({ resource, limitValue: limit, actualValue: usageAfter[key] });
}
}
}

// Температура: подія створюється при виході за межі діапазону
const isOutNow = isTemperatureOutOfRange(curr.temperature, room);
const wasOut = prev ? isTemperatureOutOfRange(prev.temperature, room) : false;
if (isOutNow && !wasOut) {
const limitValue = curr.temperature > room.tempMax ? room.tempMax : room.tempMin;
violations.push({ resource: 'temperature', limitValue, actualValue: curr.temperature });
}

return violations;
}

// Стан кімнати для індикації: normal, warning (використано більше порогу) або violation
function evaluateState({ room, usage, temperature, warningRatio }) {
const isTempOut = temperature !== null && temperature !== undefined
&& isTemperatureOutOfRange(temperature, room);

const ratios = usage
? [usageRatio(usage.water, room.waterLimit), usageRatio(usage.light, room.lightLimit)]
: [];

if (isTempOut || ratios.some((ratio) => ratio > 1)) {
return 'violation';
}
if (ratios.some((ratio) => ratio >= warningRatio)) {
return 'warning';
}
return 'normal';
}

// Дозволені режими світла залежать від залишку ліміту світла.
// Без активного бронювання світло вмикати не можна.
function allowedLightModes({ room, usage, warningRatio }) {
if (!usage) {
return ['off'];
}

const ratio = usageRatio(usage.light, room.lightLimit);
if (ratio >= 1) {
return ['off'];
}
if (ratio >= warningRatio) {
return ['off', 'low'];
}
return [...LIGHT_MODES];
}

// Використання лімітів бронювання (для ресурсної панелі та Android-застосунку)
function limitUsage(room, booking) {
const describe = (used, limit) => ({
used: round(used, 2),
limit,
left: round(Math.max(0, limit - used), 2),
percent: limit > 0 ? Math.round((used / limit) * 100) : 0,
});

return {
water: describe(booking.waterUsed, room.waterLimit),
light: describe(booking.lightUsed, room.lightLimit),
};
}

// Добовий агрегат за вимірюваннями однієї кімнати (відсортованими за часом)
function computeDailyAggregate(measurements, config) {
if (measurements.length === 0) {
return null;
}

const temps = measurements.map((m) => m.temperature);
const lights = measurements.map((m) => m.illuminance);

let waterUsed = 0;
let lightUsage = 0;
for (let i = 1; i < measurements.length; i += 1) {
const usage = usageBetween(measurements[i - 1], measurements[i], config);
waterUsed += usage.water;
lightUsage += usage.light;
}

return {
tempMin: Math.min(...temps),
tempMax: Math.max(...temps),
tempAvg: average(temps),
lightMin: Math.min(...lights),
lightMax: Math.max(...lights),
lightAvg: average(lights),
waterUsed: round(waterUsed, 2),
lightUsage: round(lightUsage, 2),
};
}

// Зведення вимірювань (відсортованих за часом) у проміжки по bucketMinutes хвилин
// від моменту fromMs - точки графіка ресурсної панелі. Для кожного проміжку:
// середні температура й освітленість, останні рівень води та режим світла.
function bucketMeasurements(measurements, fromMs, bucketMinutes) {
const sizeMs = bucketMinutes * 60 * 1000;
const buckets = new Map();

for (const m of measurements) {
const index = Math.floor((new Date(m.measuredAt).getTime() - fromMs) / sizeMs);
if (index < 0) {
continue;
}
if (!buckets.has(index)) {
buckets.set(index, []);
}
buckets.get(index).push(m);
}

return [...buckets.entries()]
.sort((a, b) => a[0] - b[0])
.map(([index, items]) => {
const last = items[items.length - 1];
return {
from: new Date(fromMs + index * sizeMs),
temperature: average(items.map((m) => m.temperature)),
illuminance: average(items.map((m) => m.illuminance)),
waterLevel: last.waterLevel,
lightMode: last.lightMode,
count: items.length,
};
});
}

LIGHT_MODES,
usageBetween,
isTemperatureOutOfRange,
detectViolations,
evaluateState,
allowedLightModes,
limitUsage,
computeDailyAggregate,
bucketMeasurements,
round,
};

'use strict';

const { HttpError } = require('../middleware/errors');

// Дозволені переходи статусу сервісної заявки: new -> in_progress -> resolved
// (заявку можна одразу закрити зі статусу new). Повернення назад заборонене.
const NEXT_STATUSES = {
  new: ['in_progress', 'resolved'],
  in_progress: ['resolved'],
  resolved: [],
};

function checkStatusChange(currentStatus, newStatus) {
  // Невідомий статус відхилить валідація моделі (400)
  const isKnownStatus = Object.hasOwn(NEXT_STATUSES, newStatus);
  if (!isKnownStatus || newStatus === currentStatus) {
    return;
  }

  const allowed = NEXT_STATUSES[currentStatus] || [];
  if (!allowed.includes(newStatus)) {
    throw new HttpError(409, `Status cannot be changed from "${currentStatus}" to "${newStatus}"`);
  }
}

'use strict';

const { Op } = require('sequelize');
const { HttpError } = require('../middleware/errors');
const { dayRange, localDateTime, previousDate, shiftDate } = require('../utils');
const { computeDailyAggregate } = require('./resources');

// Пакетна обробка: розрахунок добових агрегатів для кожної кімнати
// та зберігання архіву сирих вимірювань протягом measurementRetentionDays діб
function createAggregateService({ models, config }) {
const { Room, Measurement, DailyAggregate } = models;

const today = (now = new Date()) => localDateTime(now, config.timeZone).date;

// Найраніша дата, за яку ще зберігаються сирі вимірювання
const retentionStartDate = (todayDate) => shiftDate(todayDate, -config.measurementRetentionDays);

// Розраховує (або перераховує) агрегати за дату YYYY-MM-DD за київським часом
async function calculateForDate(date) {
const { from, to } = dayRange(date, config.timeZone);
const rooms = await Room.findAll({ order: [['id', 'ASC']] });
const results = [];

for (const room of rooms) {
const measurements = await Measurement.findAll({
where: { roomId: room.id, measuredAt: { [Op.gte]: from, [Op.lt]: to } },
order: [['measuredAt', 'ASC']],
});

const values = computeDailyAggregate(measurements, config);
if (!values) {
continue;
}

const [aggregate, isCreated] = await DailyAggregate.findOrCreate({
where: { roomId: room.id, date },
defaults: values,
});
if (!isCreated) {
await aggregate.update(values);
}
results.push(aggregate);
}

return results;
}

// Повторний розрахунок можливий лише за дати, сирі вимірювання яких ще зберігаються
function checkDateInRetention(date, now = new Date()) {
const startDate = retentionStartDate(today(now));
if (date < startDate) {
throw new HttpError(
400,
`Raw measurements are kept for ${config.measurementRetentionDays} days; the date must not be earlier than ${startDate}`,
);
}
}

// Видаляє сирі вимірювання, старші за період зберігання (агрегати зберігаються без обмеження)
async function purgeOldMeasurements(now = new Date()) {
const { from } = dayRange(retentionStartDate(today(now)), config.timeZone);
return Measurement.destroy({ where: { measuredAt: { [Op.lt]: from } } });
}

// Нічне завдання: агрегати за попередню добу, дорахунок дат, пропущених,
// поки сервер був вимкнений (якщо вимірювання ще зберігаються), і очищення архіву
async function runNightly(now = new Date()) {
const yesterday = previousDate(today(now));
const calculated = [];

for (let date = retentionStartDate(today(now)); date <= yesterday; date = shiftDate(date, 1)) {
const isMissing = await DailyAggregate.count({ where: { date } }) === 0;
if (date === yesterday || isMissing) {
const items = await calculateForDate(date);
if (date === yesterday || items.length > 0) {
calculated.push({ date, rooms: items.length });
}
}
}

const purged = await purgeOldMeasurements(now);
return { calculated, purged };
}

return { calculateForDate, checkDateInRetention, purgeOldMeasurements, runNightly };
}

module.exports = { createAggregateService };

'use strict';

// Автоматична зміна статусів бронювань (запускається планувальником щохвилини)
function createBookingJobs({ models, config, log }) {
  const { Booking } = models;

  // Дії планувальника записуються в журнал без користувача (userId = null)
  const systemRequest = {};

  async function updateBookingStatuses(now = new Date()) {
    let cancelled = 0;
    let completed = 0;

    // Не поселилися вчасно - бронювання скасовується з причиною no-show
    const notStarted = await Booking.findAll({
      where: { status: 'created', startTime: { [Op.lt]: now } },
    });
    for (const booking of notStarted) {
      if (isNoShow(booking, now, config)) {
        await booking.update({ status: 'cancelled', cancelReason: 'no-show' });
        await log(systemRequest, 'auto_cancel', 'Booking', booking.id, 'no-show');
        cancelled += 1;
      }
    }

    // Час бронювання минув - активне бронювання завершується
    const active = await Booking.findAll({
      where: { status: 'active', endTime: { [Op.lte]: now } },
    });
    for (const booking of active) {
      if (isExpired(booking, now)) {
        await booking.update({ status: 'completed' });
        await log(systemRequest, 'auto_complete', 'Booking', booking.id, 'end time reached');
        completed += 1;
      }
    }

    return { cancelled, completed };
  }

  return { updateBookingStatuses };
}

      return;

      roomId,
      status: { [Op.in]: BUSY_STATUSES },
      startTime: { [Op.lt]: end },
      endTime: { [Op.gt]: start },
    };
    if (selfId) {
      where.id = { [Op.ne]: selfId };
    }

    const overlapping = await Booking.findOne({ where });
    if (overlapping) {
      throw new HttpError(409, 'The room is already booked for this time');
    }

    }

    if (data.status === 'cancelled' && item.startTime <= new Date()) {
      throw new HttpError(409, 'A booking can be cancelled only before it starts');
    }
  };

      checkResidentCanChange(item, data);

      data.userId = forOtherUser ? requireInteger(req.body.userId, 'userId') : req.user.id;

      if (!isAdmin(req)) {
        rules.checkActiveBookingsLimit(await countActiveBookings(req.user.id, now), config);
      }

    }
    if (req.query.to) {
      where.startTime = { [Op.lt]: parseDate(req.query.to, 'to') };
    }

const { HttpError } = require('../middleware/errors');

// (порт і каталог фото задаються під час запуску) або взагалі не задаються у файлі (секрети, шлях до БД)
const FIXED_KEYS = ['port', 'uploadsDir', 'jwtSecret', 'llmApiKey', 'dbStorage', 'settingsFile'];

const TIME_PATTERN = /^([01]\d|2[0-3]):[0-5]\d$/;

function readSettingsFile(file) {
try {
return JSON.parse(fs.readFileSync(file, 'utf8'));
} catch (err) {
throw new HttpError(400, `Cannot read settings file: ${err.message}`);
}
}

// Перевіряє нові значення параметрів. Не звертається до файлів і БД,
// тому перевіряється модульними тестами. За помилки кидає HttpError 400.
function validateSettings(next, current) {
const errors = [];

for (const [key, value] of Object.entries(next)) {
if (!Object.hasOwn(current, key)) {
errors.push(`unknown parameter "${key}"`);
} else if (typeof value !== typeof current[key] || value === null) {
errors.push(`"${key}" must be of type ${typeof current[key]}`);
} else if (typeof value === 'number' && (!Number.isFinite(value) || value < 0)) {
errors.push(`"${key}" must be a non-negative number`);
}
}

if (errors.length === 0) {
const s = { ...current, ...next };

if (s.minBookingHours > s.maxBookingHours) {
errors.push('minBookingHours must not exceed maxBookingHours');
}
if (s.maxActiveBookingsPerUser < 1 || s.measurementRetentionDays < 1) {
errors.push('maxActiveBookingsPerUser and measurementRetentionDays must be at least 1');
}
if (s.defaultTempMin >= s.defaultTempMax) {
errors.push('defaultTempMin must be less than defaultTempMax');
}
if (!(s.limitWarningRatio > 0 && s.limitWarningRatio <= 1)) {
errors.push('limitWarningRatio must be in range (0, 1]');
}
if (!TIME_PATTERN.test(s.nightlyJobTime)) {
errors.push('nightlyJobTime must be in format HH:MM');
}
const powers = s.lightModePower || {};
if (!LIGHT_MODES.every((mode) => typeof powers[mode] === 'number' && powers[mode] >= 0)) {
errors.push(`lightModePower must contain non-negative numbers for: ${LIGHT_MODES.join(', ')}`);
}
}

if (errors.length > 0) {
throw new HttpError(400, `Invalid settings: ${errors.join('; ')}`);
}
}

// Текстовий опис змінених параметрів для журналу дій: "maxBookingHours: 24 -> 12"
function listChanges(before, after, keys) {
const changes = [];
for (const key of keys) {
const oldValue = JSON.stringify(before[key]);
const newValue = JSON.stringify(after[key]);
if (oldValue !== newValue) {
changes.push(`${key}: ${oldValue} -> ${newValue}`);
}
}
return changes.join('; ').slice(0, 500);
}

// Перечитує settings.json і застосовує нові значення без перезапуску сервера.
// Усі модулі читають параметри з того самого об'єкта config у момент виконання,
// тому зміни діють одразу.
function createSettingsService({ config }) {
function reload() {
const fromFile = readSettingsFile(config.settingsFile);
if (!fromFile || typeof fromFile !== 'object' || Array.isArray(fromFile)) {
throw new HttpError(400, 'Settings file must contain a JSON object');
}

const applicable = {};
for (const [key, value] of Object.entries(fromFile)) {
if (!FIXED_KEYS.includes(key)) {
applicable[key] = value;
}
}

validateSettings(applicable, config);

const before = { ...config };
Object.assign(config, applicable);
return { changes: listChanges(before, config, Object.keys(applicable)) };
}

return { reload };
}

'use strict';

const { Router } = require('express');
const { Op } = require('sequelize');
const { HttpError, asyncHandler } = require('./middleware/errors');
const { pick, parsePaging, describeChanges } = require('./utils');

const ALL_OPERATIONS = ['list', 'get', 'create', 'update', 'remove'];

// Будує стандартний CRUD-роутер для моделі.
// Особливості кожної сутності задаються через параметри (поля, guards, prepare тощо).
function buildCrud(options) {
  const {
    Model,
    entity,
    log,
    createFields = [],
    updateFields = [],
    filterFields = [],
    booleanFilters = [],
    extraWhere = () => ({}),
    scope = async () => ({}),
    prepare = async (req, data) => data,
    serialize = (req, item) => item,
    guards = {},
    lock = null,
    only = ALL_OPERATIONS,
    order = [['id', 'ASC']],
    logFields = updateFields,
    beforeRemove = async () => {},
  } = options;

  const router = Router();

  const guardsFor = (operation) => guards[operation] || [];
  const runExclusively = (task) => (lock ? lock.run(task) : task());

  // Шукає запис за id з урахуванням доступу користувача (scope)
  const findOr404 = async (req) => {
    const where = { id: req.params.id, ...(await scope(req)) };
    const item = await Model.findOne({ where });
    if (!item) {
      throw new HttpError(404, `${entity} not found`);
    }
    return item;
  };

  // Будує умови пошуку зі звичайних і булевих query-параметрів
  const buildFilters = (query) => {
    const where = {};

    for (const field of filterFields) {
      const value = query[field];
      if (value === undefined) {
        continue;
      }

      if (typeof value !== 'string') {
        throw new HttpError(400, `Query parameter "${field}" must be a single value`);
      }
      where[field] = value;
    }

    for (const field of booleanFilters) {
      const value = query[field];
      if (value === undefined) {
        continue;
      }

      if (value !== 'true' && value !== 'false') {
        throw new HttpError(400, `Query parameter "${field}" must be "true" or "false"`);
      }
      where[field] = value === 'true';
    }

    return where;
  };

  if (only.includes('list')) {
    router.get('/', ...guardsFor('list'), asyncHandler(async (req, res) => {
      // Умови поєднуються через AND, щоб обмеження доступу (scope)
      // не затирало фільтр за тим самим полем (наприклад, bookingId)
      const where = {
        [Op.and]: [buildFilters(req.query), extraWhere(req), await scope(req)],
      };

      const { limit, offset } = parsePaging(req.query);
      const { rows, count } = await Model.findAndCountAll({
        where,
        limit,
        offset,
        order,
      });

      res.json({
        total: count,
        limit,
        offset,
        items: rows.map((item) => serialize(req, item)),
      });
    }));
  }

  if (only.includes('get')) {
    router.get('/:id', ...guardsFor('get'), asyncHandler(async (req, res) => {
      const item = await findOr404(req);
      res.json(serialize(req, item));
    }));
  }

  if (only.includes('create')) {
    router.post('/', ...guardsFor('create'), asyncHandler(async (req, res) => {
      const item = await runExclusively(async () => {
        const data = await prepare(req, pick(req.body, createFields), null);
        const created = await Model.create(data);
        return created.reload();
      });

      await log(req, 'create', entity, item.id);
      res.status(201).json(serialize(req, item));
    }));
  }

  if (only.includes('update')) {
    router.put('/:id', ...guardsFor('update'), asyncHandler(async (req, res) => {
      let details = '';
      const item = await runExclusively(async () => {
        const found = await findOr404(req);
        // get({ plain: true }) повертає сам об'єкт dataValues, який update() змінює,
        // тому зберігаємо копію значень до зміни
        const before = { ...found.get({ plain: true }) };
        const data = await prepare(req, pick(req.body, updateFields), found);
        await found.update(data);
        details = describeChanges(before, found.get({ plain: true }), logFields);
        return found;
      });

      // У журнал записується, які саме поля змінилися (наприклад, роль або ліміт)
      await log(req, 'update', entity, item.id, details);
      res.json(serialize(req, item));
    }));
  }

  if (only.includes('remove')) {
    router.delete('/:id', ...guardsFor('remove'), asyncHandler(async (req, res) => {
      const item = await findOr404(req);
      await beforeRemove(req, item);
      await item.destroy();

      await log(req, 'delete', entity, item.id);
      res.status(204).end();
    }));
  }

      assert.deepEqual(r.data.allowedLightModes, ['off']);

    });

    it('третє вимірювання: перевищено воду й світло, створено дві події', async () => {
      const r = await send(room, t0 + 8 * MINUTE, { waterLevel: 78 });
      assert.equal(r.data.state, 'violation');
      assert.deepEqual(r.data.violations.map((v) => v.resource).sort(), ['light', 'water']);

      await booking.reload();
      assert.equal(booking.waterUsed, 12);
      assert.equal(booking.lightUsed, 0.4);
    });

    it('до події додається шаблонне пояснення (у фоні)', async () => {
      const violation = await app.waitFor(() => app.models.LimitViolation.findOne({

      assert.equal(violation.explanationSource, 'template');
      assert.match(violation.explanation, /вода/);
    });

    it('подальше вимірювання не створює повторних подій', async () => {
      const r = await send(room, t0 + 9 * MINUTE, { waterLevel: 70 });
      assert.deepEqual(r.data.violations, []);
      assert.equal(await app.models.LimitViolation.count({ where: { bookingId: booking.id } }), 2);
    });

      assert.equal(r.status, 200);
      assert.equal(r.data.lastMeasurement.waterLevel, 70);
      assert.equal(r.data.activeBookingId, booking.id);
      assert.equal(r.data.usage.water.used, 20);
      assert.equal(r.data.usage.water.left, 0);
      assert.equal(r.data.state, 'violation');

  describe('температура без активного бронювання', () => {
    it('подія створюється лише при виході за межі діапазону', async () => {
      const room = await app.createRoom();
      const base = Date.UTC(2031, 5, 1, 10);
      const temps = [22, 30, 31, 22, 15];
      const created = [];
      for (let i = 0; i < temps.length; i += 1) {
        const r = await send(room, base + i * MINUTE, { temperature: temps[i] });
        created.push(r.data.violations.map((v) => v.resource));
        assert.equal(r.data.bookingId, null);
      }
      assert.deepEqual(created, [[], ['temperature'], [], [], ['temperature']]);
    });

    it('без бронювання дозволено лише вимкнене світло', async () => {

      assert.deepEqual(r.data.allowedLightModes, ['off']);
      assert.equal(r.data.usage, null);
    });

    it('невідомий режим світла → 400', async () => {
