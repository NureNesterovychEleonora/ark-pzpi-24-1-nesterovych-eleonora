Харків - 2026

1. Мета роботи
Ознайомитися з процесом розроблення серверної частини програмної системи: спроєктувати базу даних (БД), розробити прикладний програмний інтерфейс (API) для взаємодії з клієнтами та перевірити їхню спільну роботу. Набути навичок побудови UML-діаграм та ER-діаграм, розроблення БД, програмної реалізації API, а також роботи з репозиторіями Git і створення технічної документації.

2. Завдання
Для програмної системи «Програмна система для керування ресурсами навчального житлового модуля» (HabiCore) виконати такі завдання:
    • сформулювати архітектурні рішення для серверної частини, клієнтських взаємодій та БД, описати моделі та зв’язки між ними;
    • створити UML-діаграму прецедентів і ER-діаграму даних;
    • спроєктувати таблиці БД, описати нормалізацію (1НФ, 2НФ, 3НФ) і створити діаграму структури БД;
    • розробити функції роботи з БД засобами ORM з підтримкою операцій CRUD для основних сутностей;
    • обрати тип API, описати ендпоінти, створити специфікацію API та програмну реалізацію;
    • перевірити взаємодію API з БД і підготувати автоматизовані тести серверної частини;
    • оформити звіт, завантажити його у форматі PDF на платформу dl.nure.ua, а текстову версію звіту та код - у репозиторій GitHub.

3. Опис виконаної роботи
Роботу виконано відповідно до документа Vision & Scope [1]. Репозиторій проєкту розміщено на платформі GitHub: https://github.com/NureNesterovychEleonora/arkpz-pzpi-24-1-nesterovych-eleonora

3.1 Архітектура серверної частини
Серверна частина системи HabiCore реалізована як монолітний Web API. Вона є єдиною точкою доступу до даних для веб-клієнта, мобільного застосунку на Android та IoT-пристрою. Архітектура складається з трьох шарів:
    • шар маршрутизації HTTP (каталог src/routes): приймає запити, перевіряє права доступу та формує відповіді;
    • шар доступу до даних: моделі ORM Sequelize, описані у файлі src/models.js (додаток А);
    • шар зберігання: файл БД SQLite.

Наскрізну функціональність винесено в окремі модулі: автентифікацію та перевірку ролей, обробку помилок і журнал дій (додаток Г). Типові операції створення, читання, оновлення та видалення (CRUD) реалізовано один раз у універсальному генераторі маршрутів src/crud.js (додаток Б) та підключено до всіх сутностей, що зменшує дублювання коду. Специфічні правила (наприклад, перевірка перетину бронювань) задаються параметрами генератора у модулях маршрутів (додаток В).
Веб-клієнт і мобільний застосунок надсилають запити із заголовком Authorization: Bearer <токен JWT>, де токен видається користувачеві під час входу; IoT-пристрій автентифікується власним ключем у заголовку X-Device-Key. Усі дані передаються у форматі JSON.

3.2 Вибір технологій
Мову JavaScript (Node.js) і фреймворк Express обрано з урахуванням документа Vision & Scope [1, 3]: вони забезпечують просту маршрутизацію запитів і єдину мову розроблення для всієї серверної частини. Для роботи з БД використано ORM Sequelize [2], яка відображає таблиці на моделі, перевіряє дані перед записом і підтримує зовнішні ключі. СУБД SQLite [5] обрано, оскільки БД зберігається в одному файлі, не потребує окремого сервера та підходить для розгортання в одному контейнері.
Автентифікація виконується за допомогою JSON Web Token [7], паролі зберігаються лише у вигляді хешів bcrypt. Специфікація API формується у форматі OpenAPI 3 [4] та відображається засобом Swagger UI. Тестування виконується вбудованим засобом Node.js node:test [6].

3.3 Моделі та зв’язки між ними
У системі визначено дев’ять моделей (таблиць):
    • User (users) - користувач із роллю resident (мешканець) або admin (адміністратор) і ознакою блокування;
    • Room (rooms) - кімната з ресурсними лімітами (вода та світло на бронювання, допустимий діапазон температури), ключем пристрою та токеном QR-коду;
    • Booking (bookings) - бронювання кімнати користувачем зі статусом created, active, completed або cancelled;
    • Measurement (measurements) - вимірювання рівня води, освітленості та температури від пристрою кімнати, яке може бути прив’язане до активного бронювання;
    • DailyAggregate (daily_aggregates) - добові агрегати вимірювань кімнати;
    • LimitViolation (limit_violations) - зафіксоване перевищення ліміту з поясненням і джерелом пояснення (llm або template);
    • Inspection (inspections) - огляд кімнати під час поселення (checkin) або виселення (checkout) зі станом ok чи issues та необов’язковою приміткою;
    • ServiceRequest (service_requests) - сервісна заявка з описом, посиланням на фото та статусом new, in_progress, resolved;
    • ActionLog (action_logs) - журнал дій користувачів.

Усі зв’язки між моделями мають тип «один-до-багатьох»: користувач і кімната мають багато бронювань і сервісних заявок; кімната має багато вимірювань, добових агрегатів і перевищень; бронювання має багато вимірювань і перевищень та не більше двох оглядів (по одному кожного типу); користувач виконує багато дій у журналі. Правила видалення задано явно: для бронювань і заявок - RESTRICT (запис, на який є посилання, видалити не можна), для вимірювань, агрегатів і перевищень кімнати та оглядів бронювання - CASCADE, для необов’язкових посилань - SET NULL.

3.4 UML-діаграма прецедентів
Діаграму прецедентів серверної частини наведено на рисунку Е.1 (додаток Е). Актори системи: мешканець, адміністратор та IoT-пристрій; адміністратор успадковує всі прецеденти мешканця. Мешканець реєструється й авторизується, переглядає каталог кімнат і бронювання за обраний день, створює бронювання (з обов’язковою перевіркою перетину), скасовує власні бронювання, записує огляди кімнат, створює сервісні заявки (фото додається за потреби) та переглядає вимірювання, добові агрегати й перевищення лімітів. Адміністратор керує кімнатами та їхніми лімітами, користувачами (зокрема блокує їх), бронюваннями, добовими агрегатами та записами про перевищення, опрацьовує заявки зі зміною статусу, видаляє вимірювання й переглядає журнал дій. IoT-пристрій надсилає вимірювання; сервер перевіряє ключ пристрою та прив’язує вимірювання до активного бронювання кімнати.

3.5 ER-діаграма даних
ER-діаграму наведено на рисунку 1. Вона містить сутності «Користувачі», «Кімнати», «Бронювання», «Вимірювання», «Добові_агрегати», «Перевищення_лімітів», «Огляди», «Сервісні_заявки» та «Журнал_дій», їхні атрибути та зв’язки «один-до-багатьох». Кожна сутність має сурогатний первинний ключ вигляду «кімната_id»; зовнішні ключі на ER-діаграмі не показано, їх утворюють зв’язки. Кружком позначено необов’язкові зв’язки: вимірювання та перевищення можуть не мати бронювання, запис журналу може не мати користувача.

3.7 Нормалізація даних
Нормалізацію виконано на прикладі центральної бізнес-задачі системи - бронювання кімнат. Для неї побудовано універсальне відношення «Дані_бронювань», що містить атрибути бронювання, користувача, який його створив, і кімнати, що бронюється (рисунок 2). Первинним ключем відношення обрано сурогатний ключ бронювання_id, оскільки жоден природний атрибут не гарантує унікальності запису.
Рисунок 2 - Універсальне відношення «Дані_бронювань» (рисунок виконано самостійно)

Визначено функціональні залежності між атрибутами відношення (рисунок 3): усі атрибути функціонально залежать від бронювання_id; атрибути користувача (відображуване_ім’я, електронна_адреса, хеш_пароля, роль, ознака_блокування) визначаються значенням користувач_id, а атрибути кімнати (назва_кімнати, опис_кімнати, ліміти ресурсів, діапазон температури, ключ_пристрою, токен_QR) - значенням кімната_id. Види залежностей на рисунку розрізнено стилем ліній: суцільна лінія - залежність від первинного ключа, штрихова - від користувач_id, пунктирна - від кімната_id.


Рисунок 3 - Функціональні залежності відношення «Дані_бронювань» (рисунок виконано самостійно)

Першу нормальну форму (1НФ) дотримано: усі атрибути атомарні, кортежі й атрибути не впорядковані, повторюваних груп і масивів немає. Наприклад, діапазон температури кімнати зберігається двома окремими атрибутами (температура_від і температура_до), а не рядком «18-26».
Другу нормальну форму (2НФ) дотримано: відношення має простий первинний ключ, тому всі неключові атрибути повністю функціонально залежать від ключа.
Третю нормальну форму (3НФ) порушено: у відношенні є транзитивні залежності, наприклад {бронювання_id} → електронна_адреса, бо {бронювання_id} → користувач_id і {користувач_id} → електронна_адреса; аналогічно {бронювання_id} → ліміт_води, бо {бронювання_id} → кімната_id і {кімната_id} → ліміт_води. Через це відношення має аномалії: дані користувача й кімнати дублюються в кожному бронюванні (зміна ліміту кімнати потребує оновлення багатьох рядків), користувача чи кімнату не можна додати без бронювання, а видалення останнього бронювання знищує відомості про користувача й кімнату.
Для усунення аномалій відношення розкладено на три: users (атрибути користувача), rooms (атрибути кімнати) та bookings, що посилається на них зовнішніми ключами userId і roomId. Усі три відношення перебувають у 3НФ, бо їхні неключові атрибути залежать лише від первинного ключа id (рисунок Ж.1). Ліміти ресурсів залежать лише від кімнати й зберігаються в rooms, тому відомості про кімнату в бронюваннях, вимірюваннях і заявках не дублюються.
Решта таблиць (measurements, daily_aggregates, limit_violations, inspections, service_requests, action_logs) також перебувають у 3НФ: кожна має простий первинний ключ id, а неключові атрибути не залежать один від одного. Природні складені ключі (roomId, measuredAt), (roomId, date) і (bookingId, type) закріплено унікальними індексами. Поля limitValue та actualValue у таблиці limit_violations є зафіксованим історичним фактом перевищення (ліміт кімнати може згодом змінитися), тому не порушують 3НФ.

3.8 Програмна реалізація доступу до БД (ORM)
Для доступу до БД використано ORM Sequelize. Моделі й зв’язки описано у файлі src/models.js (додаток А): моделі визначаються викликом sequelize.define, а допоміжна функція link одночасно задає зв’язки hasMany і belongsTo з однаковим зовнішнім ключем та правилом видалення. Таблиці створюються методом sequelize.sync() під час запуску сервера.
Операції CRUD для всіх сутностей реалізує генератор buildCrud (додаток Б). Для кожної сутності він створює маршрути: список із фільтрацією та посторінковим виведенням (findAndCountAll), отримання за ідентифікатором (findOne), створення (create), оновлення (update) і видалення (destroy). Параметри генератора - дозволені поля, фільтри, обмеження видимості та перевірки перед збереженням - задаються в модулях маршрутів. Помилки БД (порушення унікальності, зовнішнього ключа, перевірок моделей) перетворюються на коди HTTP 409 та 400 у спільному обробнику помилок (додаток Г).

3.9 Розроблення API та його специфікація
Обрано REST API у форматі JSON: ресурси ідентифікуються адресами URL, а операції відповідають методам HTTP (GET, POST, PUT, DELETE). REST простіше реалізувати й тестувати, його підтримують усі клієнти системи (браузер, Android, ESP32), а структура даних є фіксованою, тому гнучкі запити GraphQL чи двійковий протокол gRPC не потрібні. Автентифікація користувачів виконується за токеном JWT у заголовку Authorization, пристроїв - за заголовком X-Device-Key.
Базова адреса API: http://localhost:3000/api. Повну специфікацію у форматі OpenAPI доступно за адресою /openapi.json, інтерактивну документацію (Swagger UI) - за адресою /api-docs. Ендпоінти наведено в таблиці 3. Для всіх ресурсів формат запитів і відповідей однаковий: список повертає об’єкт {total, limit, offset, items}, параметри limit (від 1 до 200) і offset (не менше 0) задають сторінку, некоректні значення повертають код 400; створення повертає код 201 і створений запис; видалення - код 204. Помилки повертаються у вигляді {"error": "...", "details": [...]}. Використовуються коди: 400 - некоректні дані, 401 - немає або недійсний токен, 403 - недостатньо прав чи обліковий запис заблоковано, 404 - запис не знайдено, 409 - конфлікт (дублікат, перетин бронювань, запис має залежні дані), 413 - занадто велике тіло запиту.

3.10 Програмна реалізація API
Серверну частину реалізовано на Node.js з Express. Застосунок збирається у файлі src/app.js, який підключає маршрути ресурсів, документацію API та обробники помилок. Основні рішення:
    • автентифікація та ролі: middleware перевіряє токен JWT, наявність користувача в БД і ознаку блокування, а потім роль (додаток Г); мешканець бачить і змінює лише власні бронювання, огляди та заявки, адміністратор має повний доступ;
    • бронювання: перед збереженням перевіряються коректність часу, тривалість до 24 годин і відсутність перетину з іншими активними чи створеними бронюваннями тієї самої кімнати; перевірка та запис виконуються послідовно (черга Mutex, додаток Б), тому паралельні запити на один слот не можуть створити перетин; мешканець може скасувати лише власне бронювання і лише до його початку (додаток В);
    • розклад кімнати: запит GET /api/rooms/{id}/bookings?date=РРРР-ММ-ДД повертає бронювання кімнати за обрану добу за київським часом; доба переводиться в межі UTC з урахуванням переходу на літній час (функція dayRange, додаток Б); мешканець отримує лише час початку, завершення та статус, без даних інших користувачів (додаток В);
    • приймання вимірювань: пристрій автентифікується ключем, значення перевіряються на тип і допустимий діапазон, а вимірювання автоматично прив’язується до активного бронювання кімнати; дублікати за парою (кімната, час) відхиляються (додаток В);
    • журнал дій: створення, оновлення та видалення записів, а також реєстрація й вхід фіксуються в таблиці action_logs;
    • початкові дані: під час першого запуску створюються адміністратор, мешканець і демонстраційні кімнати з ключами пристроїв.

Для запуску потрібно встановити Node.js версії 20 або новішої, виконати в каталозі проєкту команду npm install, а потім npm start. БД у файлі data/habicore.sqlite і всі таблиці створюються автоматично.

4. Висновки
У ході роботи спроєктовано БД серверної частини системи HabiCore, що складається з дев’яти таблиць і нормалізована до третьої нормальної форми, побудовано UML-діаграму прецедентів, ER-діаграму та діаграму структури БД. Розроблено REST API з автентифікацією за токеном JWT та розмежуванням ролей мешканця й адміністратора, реалізовано доступ до БД засобами ORM Sequelize з операціями CRUD для всіх основних сутностей, створено специфікацію API у форматі OpenAPI. Взаємодію API з БД перевірено автоматичними модульними та інтеграційними тестами (83 тести), які охоплюють основні сценарії API, права ролей, обмеження цілісності БД і одночасні запити на бронювання. Реалізація є основою для розроблення бізнес-логіки та адміністрування (лабораторна робота №3) та IoT-клієнта (лабораторна робота №4).

'use strict';

const { DataTypes } = require('sequelize');

// Допоміжні функції для правил валідації полів
const isIn = (values) => ({ isIn: [values] });
const maxLen = (n) => ({ len: [0, n] });

// Описує всі таблиці бази даних та зв'язки між ними
function initModels(sequelize) {
  // ---------- Користувачі ----------
  const User = sequelize.define('User', {
    email: {
      type: DataTypes.STRING(255),
      allowNull: false,
      unique: true,
      validate: { isEmail: true, ...maxLen(255) },
    },
    passwordHash: { type: DataTypes.STRING(100), allowNull: false },
    displayName: {
      type: DataTypes.STRING(100),
      allowNull: false,
      validate: { notEmpty: true, ...maxLen(100) },
    },
    role: {
      type: DataTypes.STRING(20),
      allowNull: false,
      defaultValue: 'resident',
      validate: isIn(['resident', 'admin']),
    },
    isBlocked: { type: DataTypes.BOOLEAN, allowNull: false, defaultValue: false },
  }, { tableName: 'users' });

  // Хеш пароля ніколи не повертається клієнту
  User.prototype.toJSON = function toJSON() {
    const values = { ...this.get() };
    delete values.passwordHash;
    return values;
  };

  // ---------- Кімнати ----------
  const Room = sequelize.define('Room', {
    name: {
      type: DataTypes.STRING(100),
      allowNull: false,
      unique: true,
      validate: { notEmpty: true, ...maxLen(100) },
    },
    description: { type: DataTypes.STRING(500), allowNull: true, validate: maxLen(500) },
    waterLimit: { type: DataTypes.FLOAT, allowNull: false, defaultValue: 100, validate: { min: 0 } },
    lightLimit: { type: DataTypes.FLOAT, allowNull: false, defaultValue: 100, validate: { min: 0 } },
    tempMin: { type: DataTypes.FLOAT, allowNull: false, defaultValue: 18 },
    tempMax: { type: DataTypes.FLOAT, allowNull: false, defaultValue: 26 },
    deviceKey: {
      type: DataTypes.STRING(64),
      allowNull: false,
      unique: true,
      defaultValue: DataTypes.UUIDV4,
    },
    qrToken: {
      type: DataTypes.STRING(64),
      allowNull: false,
      unique: true,
      defaultValue: DataTypes.UUIDV4,
    },
  }, {
    tableName: 'rooms',
    validate: {
      tempRange() {
        if (this.tempMin >= this.tempMax) {
          throw new Error('tempMin must be less than tempMax');
        }
      },
    },
  });

  // ---------- Бронювання ----------
  const Booking = sequelize.define('Booking', {
    startTime: { type: DataTypes.DATE, allowNull: false },
    endTime: { type: DataTypes.DATE, allowNull: false },
    status: {
      type: DataTypes.STRING(20),
      allowNull: false,
      defaultValue: 'created',
      validate: isIn(['created', 'active', 'completed', 'cancelled']),
    },
    cancelReason: { type: DataTypes.STRING(200), allowNull: true, validate: maxLen(200) },
  }, {
    tableName: 'bookings',
    indexes: [{ fields: ['roomId', 'startTime'] }, { fields: ['userId'] }],
  });

  // ---------- Вимірювання датчиків ----------
  const Measurement = sequelize.define('Measurement', {
    measuredAt: { type: DataTypes.DATE, allowNull: false },
    waterLevel: { type: DataTypes.FLOAT, allowNull: false, validate: { min: 0, max: 100 } },
    illuminance: { type: DataTypes.FLOAT, allowNull: false, validate: { min: 0, max: 100000 } },
    temperature: { type: DataTypes.FLOAT, allowNull: false, validate: { min: -50, max: 100 } },
  }, {
    tableName: 'measurements',
    updatedAt: false,
    indexes: [
      { unique: true, fields: ['roomId', 'measuredAt'] },
      { fields: ['bookingId'] },
    ],
  });

  // ---------- Добові агрегати ----------
  const DailyAggregate = sequelize.define('DailyAggregate', {
    date: { type: DataTypes.DATEONLY, allowNull: false },
    tempMin: { type: DataTypes.FLOAT, allowNull: false },
    tempMax: { type: DataTypes.FLOAT, allowNull: false },
    tempAvg: { type: DataTypes.FLOAT, allowNull: false },
    lightMin: { type: DataTypes.FLOAT, allowNull: false },
    lightMax: { type: DataTypes.FLOAT, allowNull: false },
    lightAvg: { type: DataTypes.FLOAT, allowNull: false },
    waterUsed: { type: DataTypes.FLOAT, allowNull: false, validate: { min: 0 } },
    lightUsage: { type: DataTypes.FLOAT, allowNull: false, validate: { min: 0 } },
  }, {
    tableName: 'daily_aggregates',
    indexes: [{ unique: true, fields: ['roomId', 'date'] }],
  });

  // ---------- Перевищення лімітів ----------
  const LimitViolation = sequelize.define('LimitViolation', {
    resource: {
      type: DataTypes.STRING(20),
      allowNull: false,
      validate: isIn(['water', 'light', 'temperature']),
    },
    limitValue: { type: DataTypes.FLOAT, allowNull: false },
    actualValue: { type: DataTypes.FLOAT, allowNull: false },
    detectedAt: { type: DataTypes.DATE, allowNull: false },
    explanation: { type: DataTypes.STRING(600), allowNull: true, validate: maxLen(600) },
    explanationSource: {
      type: DataTypes.STRING(20),
      allowNull: true,
      validate: isIn(['llm', 'template']),
    },
  }, {
    tableName: 'limit_violations',
    indexes: [{ fields: ['roomId', 'detectedAt'] }],
  });

  // ---------- Огляди кімнат (заселення / виселення) ----------
  const Inspection = sequelize.define('Inspection', {
    type: {
      type: DataTypes.STRING(20),
      allowNull: false,
      validate: isIn(['checkin', 'checkout']),
    },
    state: {

'use strict';

const { Router } = require('express');
const { Op } = require('sequelize');
const { HttpError, asyncHandler } = require('./middleware/errors');
const { pick, parsePaging } = require('./utils');

const ALL_OPERATIONS = ['list', 'get', 'create', 'update', 'remove'];

// Будує стандартний CRUD-роутер для моделі.
// Особливості кожної сутності задаються через параметри (поля, guards, prepare тощо).
function buildCrud(options) {
  const {
    Model,
    entity,
    log,
    createFields = [],
    updateFields = [],
    filterFields = [],
    booleanFilters = [],
    extraWhere = () => ({}),
    scope = async () => ({}),
    prepare = async (req, data) => data,
    serialize = (req, item) => item,
    guards = {},
    lock = null,
    only = ALL_OPERATIONS,
  } = options;

  const router = Router();

  const guardsFor = (operation) => guards[operation] || [];
  const runExclusively = (task) => (lock ? lock.run(task) : task());

  // Шукає запис за id з урахуванням доступу користувача (scope)
  const findOr404 = async (req) => {
    const where = { id: req.params.id, ...(await scope(req)) };
    const item = await Model.findOne({ where });
    if (!item) {
      throw new HttpError(404, `${entity} not found`);
    }
    return item;
  };

  // Будує умови пошуку зі звичайних і булевих query-параметрів
  const buildFilters = (query) => {
    const where = {};

    for (const field of filterFields) {
      const value = query[field];
      if (value === undefined) {
        continue;
      }

      if (typeof value !== 'string') {
        throw new HttpError(400, `Query parameter "${field}" must be a single value`);
      }
      where[field] = value;
    }

    for (const field of booleanFilters) {
      const value = query[field];
      if (value === undefined) {
        continue;
      }

      if (value !== 'true' && value !== 'false') {
        throw new HttpError(400, `Query parameter "${field}" must be "true" or "false"`);
      }
      where[field] = value === 'true';
    }

    return where;
  };

  if (only.includes('list')) {
    router.get('/', ...guardsFor('list'), asyncHandler(async (req, res) => {
      // Умови поєднуються через AND, щоб обмеження доступу (scope)
      // не затирало фільтр за тим самим полем (наприклад, bookingId)
      const where = {
        [Op.and]: [buildFilters(req.query), extraWhere(req), await scope(req)],
      };

      const { limit, offset } = parsePaging(req.query);
      const { rows, count } = await Model.findAndCountAll({
        where,
        limit,
        offset,
        order: [['id', 'ASC']],
      });

      res.json({
        total: count,
        limit,
        offset,
        items: rows.map((item) => serialize(req, item)),
      });
    }));
  }

  if (only.includes('get')) {
    router.get('/:id', ...guardsFor('get'), asyncHandler(async (req, res) => {
      const item = await findOr404(req);
      res.json(serialize(req, item));
    }));
  }

  if (only.includes('create')) {
    router.post('/', ...guardsFor('create'), asyncHandler(async (req, res) => {
      const item = await runExclusively(async () => {
        const data = await prepare(req, pick(req.body, createFields), null);
        const created = await Model.create(data);
        return created.reload();
      });

      await log(req, 'create', entity, item.id);
      res.status(201).json(serialize(req, item));
    }));
  }

  if (only.includes('update')) {
    router.put('/:id', ...guardsFor('update'), asyncHandler(async (req, res) => {
      const item = await runExclusively(async () => {
        const found = await findOr404(req);
        const data = await prepare(req, pick(req.body, updateFields), found);
        await found.update(data);
        return found;
      });

      await log(req, 'update', entity, item.id);
      res.json(serialize(req, item));
    }));
  }

  if (only.includes('remove')) {
    router.delete('/:id', ...guardsFor('remove'), asyncHandler(async (req, res) => {
      const item = await findOr404(req);
      await item.destroy();

      await log(req, 'delete', entity, item.id);
      res.status(204).end();
    }));
  }

  return router;
}

module.exports = { buildCrud };

'use strict';

const { HttpError } = require('./middleware/errors');

const DEFAULT_TIME_ZONE = 'Europe/Kyiv';

// ---------- Перевірка вхідних значень ----------

function parseDate(value, name) {
  const date = value instanceof Date ? value : new Date(value);
  const isMissing = value === undefined || value === null;

  if (isMissing || Number.isNaN(date.getTime())) {
    throw new HttpError(400, `Field "${name}" must be a valid date-time`);
  }
  return date;
}

function requireNumber(value, name) {
  if (typeof value !== 'number' || Number.isNaN(value)) {
    throw new HttpError(400, `Field "${name}" must be a number`);
  }
  return value;
}

// Приймає ціле число або рядок із цілим числом (наприклад, "5")
function requireInteger(value, name) {
  const isIntegerString = typeof value === 'string' && /^-?\d+$/.test(value.trim());
  const number = isIntegerString ? Number(value) : value;

  if (typeof number !== 'number' || !Number.isInteger(number)) {
    throw new HttpError(400, `Field "${name}" must be an integer`);
  }
  return number;
}

// Перевіряє дату у форматі YYYY-MM-DD (разом із існуванням такої дати в календарі)
function requireDateOnly(value, name) {
  const match = /^(\d{4})-(\d{2})-(\d{2})$/.exec(typeof value === 'string' ? value : '');

  if (match) {
    const year = Number(match[1]);
    const month = Number(match[2]);
    const day = Number(match[3]);

    const date = new Date(Date.UTC(year, month - 1, day));
    const isRealDate = date.getUTCFullYear() === year
      && date.getUTCMonth() === month - 1
      && date.getUTCDate() === day;

    if (isRealDate) {
      return value;
    }
  }

  throw new HttpError(400, `Field "${name}" must be a valid date in format YYYY-MM-DD`);
}

// Залишає в об'єкті лише дозволені поля
function pick(body, fields) {
  const result = {};
  for (const field of fields) {
    if (body && body[field] !== undefined) {
      result[field] = body[field];
    }
  }
  return result;
}

// Читає параметри пагінації limit та offset із query-рядка
function parsePaging(query, { defaultLimit = 50, maxLimit = 200 } = {}) {
  const readInteger = (raw, name, min, fallback) => {
    if (raw === undefined) {
      return fallback;
    }

    const isValid = typeof raw === 'string' && /^\d+$/.test(raw) && Number(raw) >= min;
    if (!isValid) {
      throw new HttpError(400, `Query parameter "${name}" must be an integer >= ${min}`);
    }
    return Number(raw);
  };

  const limit = Math.min(readInteger(query.limit, 'limit', 1, defaultLimit), maxLimit);
  const offset = readInteger(query.offset, 'offset', 0, 0);
  return { limit, offset };
}

// ---------- Робота з часовими поясами ----------

// Різниця (у мс) між місцевим часом у поясі timeZone та UTC у момент utcMs
function tzOffsetMs(timeZone, utcMs) {
  const parts = new Intl.DateTimeFormat('en-US', {
    timeZone,
    hourCycle: 'h23',
    year: 'numeric',
    month: '2-digit',
    day: '2-digit',
    hour: '2-digit',
    minute: '2-digit',
    second: '2-digit',
  }).formatToParts(new Date(utcMs));

  const values = {};
  for (const part of parts) {
    if (part.type !== 'literal') {
      values[part.type] = Number(part.value);
    }
  }

  const localAsUtc = Date.UTC(
    values.year, values.month - 1, values.day,
    values.hour, values.minute, values.second,
  );
  return localAsUtc - Math.floor(utcMs / 1000) * 1000;
}

// Переводить північ за місцевим часом у момент UTC.
// Зсув рахуємо двічі, щоб правильно обробити перехід на літній/зимовий час.
function zonedMidnightToUtc(year, month, day, timeZone) {
  const guess = Date.UTC(year, month - 1, day);
  const firstTry = guess - tzOffsetMs(timeZone, guess);
  return new Date(guess - tzOffsetMs(timeZone, firstTry));
}

// Межі доби [from, to) для дати YYYY-MM-DD у заданому часовому поясі
function dayRange(dateStr, timeZone = DEFAULT_TIME_ZONE) {
  requireDateOnly(dateStr, 'date');

  const [year, month, day] = dateStr.split('-').map(Number);
  const nextDay = new Date(Date.UTC(year, month - 1, day + 1));

  return {
    from: zonedMidnightToUtc(year, month, day, timeZone),
    to: zonedMidnightToUtc(
      nextDay.getUTCFullYear(), nextDay.getUTCMonth() + 1, nextDay.getUTCDate(), timeZone,
    ),
  };
}

// ---------- Черга виконання ----------

// Мьютекс: завдання виконуються строго по черзі.
// Потрібен, щоб два однакові бронювання не пройшли перевірку одночасно.
class Mutex {
  constructor() {
    this.tail = Promise.resolve();
  }

  run(task) {
    const result = this.tail.then(() => task());
    // Помилка одного завдання не повинна зупиняти чергу
    this.tail = result.catch(() => {});
    return result;
  }
}

const MS_IN_HOUR = 3600 * 1000;

module.exports = ({ models, config, auth, log }) => {
  const { Booking } = models;

  // Мьютекс не дає двом запитам одночасно забронювати одну кімнату
  const lock = new Mutex();

  // Перевіряє час бронювання та відсутність перетину з іншими бронюваннями
  const checkTimesAndOverlap = async (roomId, start, end, status, selfId) => {
    if (end <= start) {
      throw new HttpError(400, 'endTime must be later than startTime');
    }
    if (end - start > config.maxBookingHours * MS_IN_HOUR) {
      throw new HttpError(400, `Booking duration must not exceed ${config.maxBookingHours} hours`);
    }

    // Скасовані та завершені бронювання кімнату не займають
    if (status === 'cancelled' || status === 'completed') {
      return;
    }

    const where = {
      roomId,
      status: { [Op.in]: ['created', 'active'] },
      startTime: { [Op.lt]: end },
      endTime: { [Op.gt]: start },
    };
    if (selfId) {
      where.id = { [Op.ne]: selfId };
    }

    const overlapping = await Booking.findOne({ where });
    if (overlapping) {
      throw new HttpError(409, 'The room is already booked for this time');
    }
  };

  // Обмеження для звичайного мешканця при зміні свого бронювання
  const checkResidentCanChange = (item, data) => {
    if (item.status !== 'created') {
      throw new HttpError(409, 'Only bookings with status "created" can be changed');
    }

    const triesToChangeRoom = data.roomId !== undefined;
    const triesToSetOtherStatus = data.status && data.status !== 'cancelled';
    if (triesToChangeRoom || triesToSetOtherStatus) {
      throw new HttpError(403, 'Forbidden');
    }

    if (data.status === 'cancelled' && item.startTime <= new Date()) {
      throw new HttpError(409, 'A booking can be cancelled only before it starts');
    }
  };

  const prepare = async (req, data, item) => {
    const isAdmin = req.user.role === 'admin';

    if (item && !isAdmin) {
      checkResidentCanChange(item, data);
    }

    if (!item) {
      // Адміністратор може створити бронювання від імені іншого користувача
      const forOtherUser = isAdmin && req.body.userId !== undefined;
      data.userId = forOtherUser ? requireInteger(req.body.userId, 'userId') : req.user.id;
      data.status = 'created';
    }

    // Значення, яких немає в запиті, беремо зі збереженого бронювання
    const roomId = requireInteger(
      data.roomId !== undefined ? data.roomId : (item && item.roomId),
      'roomId',
    );
    const start = parseDate(
      data.startTime !== undefined ? data.startTime : (item && item.startTime),
      'startTime',
    );
    const end = parseDate(
      data.endTime !== undefined ? data.endTime : (item && item.endTime),
      'endTime',
    );
    const status = data.status || (item && item.status);

    await checkTimesAndOverlap(roomId, start, end, status, item && item.id);

    // Записуємо вже перевірені та приведені значення
    if (data.roomId !== undefined) {
      data.roomId = roomId;
    }
    if (data.startTime !== undefined) {
      data.startTime = start;
    }
    if (data.endTime !== undefined) {
      data.endTime = end;
    }
    return data;
  };

  // Дозволяє фільтрувати бронювання, що перетинаються з проміжком from..to
  const extraWhere = (req) => {
    const where = {};
    if (req.query.from) {
      where.endTime = { [Op.gt]: parseDate(req.query.from, 'from') };
    }
    if (req.query.to) {
      where.startTime = { [Op.lt]: parseDate(req.query.to, 'to') };
    }
    return where;
  };

  return buildCrud({
    Model: Booking,
    entity: 'Booking',
    log,
    lock,
    createFields: ['roomId', 'startTime', 'endTime'],
    updateFields: ['roomId', 'startTime', 'endTime', 'status', 'cancelReason'],

      get: [auth.authenticate],

    if (typeof password !== 'string' || password.length < MIN_PASSWORD_LENGTH) {
      throw new HttpError(400, 'Password must be at least 6 characters long');
    }

    const user = await User.create({
      email,
      displayName,
      role: 'resident',
      passwordHash: bcrypt.hashSync(password, 10),
    });

    await log({ user }, 'register', 'User', user.id);
    res.status(201).json(user);
  }));

  // Вхід: перевіряємо пароль і повертаємо JWT-токен
  router.post('/login', asyncHandler(async (req, res) => {
    const { email, password } = req.body || {};

    const user = await User.findOne({ where: { email: String(email || '') } });
    const isPasswordValid = user && bcrypt.compareSync(String(password || ''), user.passwordHash);

    if (!isPasswordValid) {
      throw new HttpError(401, 'Invalid email or password');
    }
    if (user.isBlocked) {
      throw new HttpError(403, 'Account is blocked');
    }

    const token = jwt.sign({ sub: user.id, role: user.role }, config.jwtSecret, {
      expiresIn: config.jwtExpiresIn,
    });

    await log({ user }, 'login', 'User', user.id);
    res.json({ token, user });
  }));

  router.get('/me', auth.authenticate, (req, res) => res.json(req.user));

  return router;
};

'use strict';

const jwt = require('jsonwebtoken');
const { HttpError, asyncHandler } = require('./errors');

// Створює middleware для автентифікації (JWT) та перевірки ролей.
function createAuth(models, config) {
  const authenticate = asyncHandler(async (req, res, next) => {
    // Очікуваний заголовок: "Authorization: Bearer <token>"
    const header = req.headers.authorization || '';
    const [scheme, token] = header.split(' ');
    if (scheme !== 'Bearer' || !token) {
      throw new HttpError(401, 'Authentication required');
    }

    let payload;
    try {
      payload = jwt.verify(token, config.jwtSecret);
    } catch (e) {
      throw new HttpError(401, 'Invalid or expired token');
    }

    const user = await models.User.findByPk(payload.sub);
    if (!user) {
      throw new HttpError(401, 'User no longer exists');
    }
    if (user.isBlocked) {
      throw new HttpError(403, 'Account is blocked');
    }

    req.user = user;
    next();
  });

  const requireRole = (...roles) => (req, res, next) => {
    if (roles.includes(req.user.role)) {
      return next();
    }
    return next(new HttpError(403, 'Forbidden'));
  };

  const adminOnly = [authenticate, requireRole('admin')];

  return { authenticate, requireRole, adminOnly };
}

module.exports = { createAuth };

'use strict';

class HttpError extends Error {
  constructor(status, message) {
    super(message);
    this.status = status;
  }
}

// Обгортка для async-обробників: будь-яка помилка передається в next(),
// тому її обробить errorHandler.
const asyncHandler = (handler) => (req, res, next) =>
  new Promise((resolve) => resolve(handler(req, res, next))).catch(next);

function isClientErrorStatus(status) {
  return Number.isInteger(status) && status >= 400 && status < 500;
}

// Єдине місце, де помилки перетворюються на HTTP-відповіді.
function errorHandler(err, req, res, next) {
  if (err instanceof HttpError) {
    return res.status(err.status).json({ error: err.message });
  }

  // Некоректний JSON у тілі запиту
  if (err.type === 'entity.parse.failed') {
    return res.status(400).json({ error: 'Invalid JSON body' });
  }

  if (isClientErrorStatus(err.status)) {
    return res.status(err.status).json({ error: err.message });
  }

  if (err.name === 'SequelizeUniqueConstraintError') {
    return res.status(409).json({ error: 'Record with such unique value already exists' });
  }

  if (err.name === 'SequelizeValidationError') {
    return res.status(400).json({
      error: 'Validation failed',
      details: err.errors.map((e) => e.message),
    });
  }

  if (err.name === 'SequelizeForeignKeyConstraintError') {
    const isDelete = req.method === 'DELETE';
    const status = isDelete ? 409 : 400;
    const message = isDelete
      ? 'Record is referenced by other records'
      : 'Referenced record does not exist';
    return res.status(status).json({ error: message });
  }

  console.error(err);
  return res.status(500).json({ error: 'Internal server error' });
}

module.exports = { HttpError, asyncHandler, errorHandler };

  await sequelize.sync();

  });

  let counter = 0;
  const unique = (prefix) => { counter += 1; return `${prefix}-${counter}`; };

    const res = await fetch(base + path, {
      method,
      headers: {
        ...(body !== undefined || rawBody !== undefined ? { 'Content-Type': 'application/json' } : {}),
        ...(token ? { Authorization: `Bearer ${token}` } : {}),
        ...headers,
      },
      body: rawBody !== undefined ? rawBody : (body !== undefined ? JSON.stringify(body) : undefined),
    });
    const text = await res.text();
    let data = null;
    try {
      data = text ? JSON.parse(text) : null;
    } catch (e) {
      data = text;
    }
    return { status: res.status, data, headers: res.headers };
